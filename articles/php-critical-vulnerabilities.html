PHP's Critical Security Flaws: What Happened and What To Do

ALZ Technology22 Oct 20262 min read

On 21 October 2026, the PHP project released urgent security updates for two critical vulnerabilities, CVE-2026-109618 and CVE-2026-109619. Both are rated 9.2 under CVSS v4.0 and can allow an attacker with no login to run their own code on an unpatched web server. PHP still powers a large share of the world's websites, so this one matters.

What happened

Both flaws sit deep inside PHP's memory management and error handling, parts of the language that nearly every web request touches. According to the PHP Foundation, the first (CVE-2026-109618) can corrupt memory when a request hits PHP's memory limit at exactly the wrong moment. The second (CVE-2026-109619) can leave a worker process pointing at memory from a previous request, a classic "use after free" bug. Researchers demonstrated full remote code execution on Apache with mod_php using default settings.

The Canadian Centre for Cyber Security reports that proof-of-concept exploit code is publicly available. No active exploitation had been confirmed at the time of its alert, but that can change quickly.

Who is at risk

  • Any server running PHP for the web, including PHP-FPM, Apache with mod_php, php-cgi, FrankenPHP and LiteSpeed. Risk is highest for mod_php.
  • Internet-facing sites: WordPress and other CMS sites, online shops, booking systems and customer portals built on PHP.
  • Old PHP versions. PHP 8.1 and earlier no longer receive official fixes, so those servers stay vulnerable unless a vendor backports a patch.

Hosted platforms that run their own servers are responsible for patching their side. Static websites with no server-side code are not affected.

What businesses should do now

  • Upgrade immediately to a fixed release: 8.5.12, 8.4.27, 8.3.36 or 8.2.35. The PHP team says there is no complete mitigation; updating is the only safe choice.
  • Restart PHP workers after upgrading and confirm the running version, not just the installed package.
  • Check what bundles PHP: containers, appliances, plugins and third-party products. Note that some managed tools' automatic updates do not cover PHP.
  • Prioritise internet-facing systems, and isolate anything you cannot patch yet.
  • Review logs for unusual processes, new accounts, unexpected files or outbound connections from web servers.
  • Ask your vendors (web agency, hosting provider, SaaS suppliers) to confirm in writing that they have patched.

For individuals: watch for the phishing wave

Big security news is a gift to scammers. Expect emails and messages that borrow the headline to create urgency, such as "your account ID is expiring", "urgent security maintenance" or "reset your password now".

  • Do not click links in unexpected security emails. Open the site by typing its address yourself.
  • Check the real sender address, not just the display name.
  • Turn on two-factor authentication for email, banking, payment and exchange accounts.
  • Never reuse passwords, and keep an eye on card and bank statements for unfamiliar charges.

The takeaway

Patch fast, verify the version that is actually running, and treat any urgent "security" email with suspicion. Good hygiene beats panic.
